## ① 개발자 계정 만들기 (처음 한 번)

1. PC 나 폰 브라우저에서 **play.google.com/console** → 가입
2. 계정 종류: **개인(Personal)** 선택
   (회사·조직 계정은 D-U-N-S 번호가 필요해 오래 걸림. 개인 계정은 아래 ⑥ 비공개 테스트가 필수)
3. 개발자 이름: 스토어에 보이는 이름 (예: "jeongguskbag" 또는 원하는 브랜드명)
4. 연락처 이메일·전화번호 확인 → **등록비 25달러** 결제
5. **본인 확인**: 신분증 사진 업로드 → 보통 며칠 안에 승인 메일
6. **안드로이드 기기 확인**: 폰에 "Play Console" 앱 설치 → 같은 계정으로 로그인하면 확인됨

## ② 결제 프로필 (유료 앱이라 필수)

Play Console → **설정 → 결제 프로필** → 만들기
- 이름·주소·은행 계좌(원화 입금 계좌)·세금 정보 입력
- 유료 앱을 파는 개발자는 **주소가 스토어에 공개**됩니다
- 이게 없으면 앱 가격을 정할 수 없습니다

## ③ 앱 만들기

Play Console → **모든 앱 → 앱 만들기**

| 칸 | 입력 |

| 선언(정책·미국 수출법) | 체크 |

## ⑤ 스토어 등록정보

**스토어 등록정보 → 기본 스토어 등록정보**
- 앱 이름·간단한 설명·자세한 설명: `store/LISTING.md` 의 한국어 부분 그대로 붙여넣기
- 앱 아이콘: `store/icon-512.png` · 그래픽 이미지: `store/feature-graphic-ko.png` · 휴대폰 스크린샷 2장 이상
- 다른 언어 3개: 같은 화면 위쪽 **번역 관리 → 직접 번역 추가** → **영어(미국) en-US, 일본어 ja-JP, 중국어(간체) zh-CN** 체크 → 추가
  → 위쪽 언어 선택에서 언어를 바꿔 가며 `LISTING.md` 의 English / 日本語 / 简体中文 부분(이름·간단한 설명·자세한 설명)을 붙여넣기
  → 그래픽 이미지도 언어별로: `feature-graphic-en.png` / `-ja.png` / `-zh.png` (아이콘·스크린샷은 비워 두면 한국어 것을 그대로 씀)
  → "기계 번역 사용" 제안이 나와도 직접 넣은 문구를 쓰세요

**스토어 설정**: 카테고리 **도구**, 연락처 이메일

**가격**: 수익 창출 → 제품 → **앱 가격** → 2,900원 → "다른 국가 가격 자동 변환" 사용 → 저장

## ⑥ 비공개 테스트 (12명 이상, 14일 연속)

자세한 방법·모집 글은 `store/TESTERS.md`. 요약:

1. 테스트 및 출시 → 테스트 → **비공개 테스트** → 트랙 만들기
2. **국가/지역**: 대한민국 추가
3. **테스터**: 이메일 목록 만들기 → 모은 Gmail 15~20개 붙여넣기
4. **새 버전 만들기** →
   - 처음이면 **Play 앱 서명** 안내가 나옴 → "Google에서 생성한 앱 서명 키 사용"(기본값) 그대로 계속
     (우리가 GitHub Secrets 에 넣은 키는 "업로드 키"가 됨. 잃어버려도 Play 고객센터에서 재설정 가능)
   - `app-release.aab` 업로드 → 출시 노트(`TESTERS.md` 5번) 붙여넣기 → 다음
   - **민감한 권한** 경고가 나오면 → 앱 콘텐츠 → **모든 패키지 쿼리(QUERY_ALL_PACKAGES)** 신고서 작성
     (`LISTING.md` 5번 문구 붙여넣기)
5. **검토를 위해 변경사항 보내기** → 첫 검토 며칠
6. 검토 통과 후 테스터 탭의 **"웹에서 참여" 링크** + 프로모션 코드를 테스터에게 보내기
7. **14일 동안 트랙을 멈추거나 새로 만들지 말기** (일시중지하면 날짜가 다시 시작될 수 있음).
   이 기간에 고칠 게 생기면 같은 트랙에 새 버전을 올리면 됩니다 (versionCode 올려서)

## ⑦ 프로덕션 액세스 신청

12명 이상이 14일 연속 참여하면 대시보드에 **프로덕션 액세스 신청** 버튼이 열림
- 테스트를 어떻게 했는지, 테스터 의견, 고친 점, 출시 준비가 됐다고 보는 이유를 묻는 설문 → 솔직하게 몇 줄씩
- 답변 검토는 보통 일주일 안팎

## ⑧ 정식 출시

1. 테스트 및 출시 → **프로덕션** → 국가/지역: 대한민국(원하면 다른 나라도)
2. **새 버전 만들기** → "라이브러리에서 추가"로 테스트에 올린 같은 버전을 고르거나 새 AAB 업로드
3. 검토 → 통과하면 스토어에 공개 (검토 며칠)

## 업데이트 올릴 때마다

1. 코드 수정 후 `app/build.gradle.kts` 의 **versionCode 를 1 올리기** (versionName 도 0.6.0 → 0.6.1 등)
   — 같은 versionCode 는 다시 올릴 수 없음
2. GitHub → Actions → **Release build** → Run workflow → `ApkVault-release` 의 `app-release.aab`
3. Play Console → 프로덕션(또는 테스트 트랙) → 새 버전 만들기 → 업로드 → 출시 노트 → 검토 보내기

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| "이 버전 코드는 이미 사용됨" | versionCode 올려서 다시 빌드 |
| "API 수준 36 이상을 타깃해야 함" | targetSdk 를 요구 수준으로 올려 다시 빌드 |
| "서명되지 않은 번들" / 업로드 키 불일치 | GitHub Secrets 의 키로 만든 `ApkVault-release` 를 올렸는지 확인 (debug 빌드는 올릴 수 없음) |
| 가격 칸이 안 보임 | ② 결제 프로필 먼저 |
| 프로덕션 신청 버튼이 안 열림 | 참여 중인 테스터 12명 이상인지, 14일 지났는지 |
| QUERY_ALL_PACKAGES 거절 | 신고서에 "설치된 앱 백업이 유일한 핵심 기능"임을 강조하고 30초 데모 영상 링크 추가 |
